# AGENT.md — Quick Reference for ansible-demo

## Project Overview

This project demonstrates **two approaches** for running Ansible automation on Deckhouse Virtualization (DVP):

1. **Ansible via Cloud-init** — VM pulls playbook from GitHub during initialization
2. **AWX Integration** — Enterprise Ansible automation with automatic VM inventory discovery

## Important Nuances

### 1. Cloud-init Ansible Pull

- **User**: `ansible` (password: `ansible`)
- **Playbook URL**: `https://github.com/fl64/ansible-demo.git`
- **Playbook**: `demo-project/playbooks/test-playbook.yml`
- **Key**: SSH key must be generated via `task ssh-gen` and injected via `task ssh-update-cloudinit`
- VM pulls playbook **on every boot** (AlwaysOn policy)

### 2. AWX Configuration

- **Operator version**: `2.19.1` (defined in Taskfile.yml)
- **Namespace**: `awx-instance` (configurable via `AWX_INSTANCE_NS`)
- **OIDC (Dex)**: Enabled by default, uses Python syntax in `orgMap`
- **Database**: Standalone PostgreSQL, 2 CPU cores, 4Gi RAM, 10Gi storage

### 3. OIDC Configuration Gotcha

In `charts/awx-instance/values.yaml`, OIDC org mapping uses **Python syntax**:

```yaml
# CORRECT - Python True/False
orgMap: "{'Default': {'admins': True, 'users': True}}"

# WRONG - YAML booleans will cause SyntaxError in AWX
orgMap: "{'Default': {'admins': true, 'users': true}}"
```

### 4. awx-inventory Controller

- Watches `VirtualMachine` resources in specified namespace
- Creates one AWX inventory **per namespace**
- Host variables include: `vm_name`, `vm_namespace`, `labels`, `ansible_host`
- Requires `AWX_URL` and `AWX_TOKEN` environment variables

### 5. SSH Access to VMs

- Uses `d8 v ssh` (Deckhouse CLI) with ED25519 key
- Key location: `tmp/ssh/awx` (generated by `task ssh-gen`)
- Username: `ansible` (not `cloud`)

## Quick Commands

```bash
# Deploy VMs with cloud-init
task vm:deploy

# SSH to VM
task vm:ssh VM_NAME=demo-vm-01

# Install AWX
task awx-operator:install
task install

# Uninstall
task uninstall
task awx-operator:uninstall

# Build awx-inventory
cd awx-inventory && task build-push
```

## Environment Variables

### awx-inventory controller

| Variable | Description | Default |
|----------|-------------|---------|
| `AWX_URL` | AWX API URL | Required |
| `AWX_TOKEN` | AWX API token | Required |
| `WATCH_NAMESPACE` | K8s namespace to watch VMs | Required |
| `AWX_ORGANIZATION` | AWX organization name | `Default` |
| `INVENTORY_PREFIX` | Prefix for inventory names | `""` |
| `AWX_WAIT_TIMEOUT` | Wait for AWX availability | 300s |
| `AWX_WAIT_INTERVAL` | Check interval | 5s |

### Taskfile (root)

| Variable | Default |
|----------|---------|
| `AWX_OPERATOR_VERSION` | 2.19.1 |
| `AWX_INSTANCE_NS` | awx-instance |
| `VM_NS` | ansible-demo |
| `SSH_FILE_NAME` | awx |

## Common Issues

1. **VM has no IP** — Controller skips VMs without IP address
2. **OIDC not working** — Check Python syntax in `orgMap` (True/False, not true/false)
3. **AWX not accessible** — Ensure operator is installed first (`task awx-operator:install`)
4. **Ansible pull fails** — Check VM has network access to GitHub

## Files That Should NOT Be Committed

- `tmp/` — SSH keys and temporary files
- `my-values.yaml` — User-specific overrides (contains passwords)
- `awx-operator/manager-config.yaml` — Generated by operator
